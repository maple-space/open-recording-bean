# macOS 安装与使用指南

适用于 macOS 11 及以上的 Intel 与 Apple Silicon 电脑，已在 macOS 15 上完成功能验证。声音由录音豆采集，无需电脑内置麦克风；Recording Bean Audio 2ch 将网站收到的声音提供给输入法或会议软件。

```text
录音豆 → 蓝牙 → 本机服务
                 ├→ SenseVoice / CAM++ → 网页实时文字与说话人编号
                 └→ Recording Bean Audio 2ch → Typeless / 豆包 / 会议软件
```

## 1. 准备运行环境

- Node.js 22.12+，也支持 20.x 中的 20.19+。
- Python 3.10–3.13；如果已安装 uv，启动脚本可用它准备 Python 3.12。
- 首次联网下载依赖与约 270 MB 的语音识别、说话人模型。

可以使用 [Node.js](https://nodejs.org/) 和 [Python](https://www.python.org/downloads/) 的安装器，或通过 Homebrew 运行 `brew install node python@3.12`。Apple Silicon 请选择原生或 Universal 版本。依赖由目标电脑自行安装，无需从其他电脑复制 `.venv`、`node_modules` 或网页构建目录。

克隆源码：

```bash
git clone https://github.com/maple-space/open-recording-bean.git
cd open-recording-bean
```

## 2. 安装专属声卡

只使用网页实时文字可以跳过这一步；需要把声音送进输入法或会议软件时安装一次即可。

1. 从 [声卡 Release](https://github.com/maple-space/open-recording-bean/releases/tag/audio-v1.0.1) 下载 **`RecordingBeanAudio2ch-1.0.1-release.zip`**。这是 macOS 11+ Universal 驱动，Intel 与 Apple Silicon 共用，不需要安装 Xcode。
2. 解压后进入 `RecordingBeanAudio2ch-1.0.1/`，双击 **`安装并启用.command`**，按提示完成本机管理员认证。
3. 安装入口会检测设备。显示“声卡已就绪”后即可使用，通常无需重启电脑。设备未加载时，脚本会询问是否重新加载系统音频服务；同意后声音会短暂停顿。
4. 如果 macOS 拒绝重新加载，或设备仍未出现，保存工作后重启 macOS，再检查“系统设置 → 声音 → 输入”是否有 **Recording Bean Audio 2ch**。

也可直接打开单独的 `.pkg` 安装；设备未出现时，使用 ZIP 内的安装入口检测。驱动由 macOS 加载，无需另开声卡应用。不要把系统默认输出改成该声卡，后面只需在网站和目标应用中选择它。

**签名状态：** 当前驱动为 ad-hoc 签名，安装包未使用 Developer ID 签名或 Apple 公证。如果 macOS 因无法验证开发者而阻止打开，确认来源为本仓库 Release 后，按 [Apple 的打开应用说明](https://support.apple.com/zh-cn/102445)，在“系统设置 → 隐私与安全性”中查看“仍要打开”选项。文件损坏或恶意软件提示应另行排查，不关闭 Gatekeeper 或 SIP。

Release 的安装包只包含声卡。网站通过源码运行，模型由首次启动下载；GitHub 自动生成的 `Source code` 附件是对应标签的源码快照。

### 卸载声卡

不再使用时，可以把它从系统里移除：

1. 在网页上关闭实时输入，把输入法和会议软件的麦克风改回原来的设备。
2. 在访达的菜单里选“前往 → 前往文件夹…”，输入 `/Library/Audio/Plug-Ins/HAL/`，把里面的 `RecordingBeanAudio2ch.driver` 移到废纸篓，按提示输入管理员密码。
3. 重启 macOS。重启前它可能还留在设备列表里；重启后“系统设置 → 声音”里没有 **Recording Bean Audio 2ch**，就是卸载完成了。

卸载只移除声卡，网站、模型以及已保存的录音和文字都不受影响。以后想再用，重新运行安装入口即可。

## 3. 启动网站并连接录音豆

在源码目录运行：

```bash
./start.sh
```

脚本自动准备项目环境、安装依赖、构建网页、下载并校验模型，然后打开 <http://127.0.0.1:8875>。保持运行服务的终端窗口打开。模型下载、重试与离线拷贝详见 [首次运行指南](first-run.md)。

录音豆同一时间只能连接一个客户端。先在原电脑或手机 App 正常断开连接，再在网页搜索并连接录音豆；系统询问终端的蓝牙权限时允许。

连接后点击 **进入实时输入**。设备页折叠区“仅在录音豆上录音”用于控制保存在设备里的录音，日常传声和网页识别从实时输入页面开始。

## 4. 开始实时输入

1. 网页勾选“送到虚拟声卡，给输入法当麦克风”，输出设备选择 **Recording Bean Audio 2ch**。
2. 需要网页文字时勾选“在本页显示文字”，需要区分声音时勾选“区分说话人”，然后点击“开启实时输入”。
3. 在 Typeless、豆包或会议软件中，将麦克风选择为 **Recording Bean Audio 2ch**；系统询问该应用的麦克风权限时允许。
4. 对着录音豆说话，网页音量条和目标应用的输入电平应随声音变化。使用输入法时，将光标放进文本框并按其语音输入快捷键。

无需聚合设备或多输出设备。系统扬声器仍可播放其他声音；虚拟声卡传声时不一定会从扬声器外放。

关闭网页实时输入后，录音豆的声音会停止送入声卡。下次使用先开启网页实时输入；切回电脑自己的麦克风时，在目标应用中重新选择输入设备。

网页的 SenseVoice / CAM++ 在本机运行；Typeless、豆包等应用使用各自的识别服务与设置。

## 5. 常见问题

| 现象 | 处理方法 |
| --- | --- |
| 系统没有声卡 | 运行配套安装入口检测；无法加载时按上面的安装步骤处理。 |
| 系统有声卡，网页没有 | 关闭实时输入后刷新设备列表或页面，再选择设备。 |
| 网页音量条不动 | 检查蓝牙连接和权限、实时输入是否开启，以及手机或其他电脑是否占用录音豆。 |
| 网页有声音或文字，输入法电平不动 | 确认勾选了送到声卡，网页输出和输入法麦克风同为 Recording Bean Audio 2ch，并已授予应用麦克风权限。 |
| 输入法电平变化，但没有文字 | 检查听写快捷键、文本框焦点、输入法服务及所需系统权限。 |
| 传声正常，网页不出字 | 运行 `./start.sh models` 补齐模型，在首页点击“重新检测”，并勾选“在本页显示文字”。 |

运行 `./start.sh doctor` 可查看环境、模型和声卡状态。报告问题时请提供芯片架构、macOS 与目标应用版本、操作步骤和完整错误提示；请勿公开个人录音、文字记录或设备序列号。
