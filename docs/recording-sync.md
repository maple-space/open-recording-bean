# 把录音同步到本机资料库

设备页的 **同步全部录音** 会把当前列表里的录音保存到这台电脑。同步只保存音频，**保留录音豆里的原件，不自动转写或总结**。已在资料库中的录音会先核对本机文件，核验通过后跳过下载。

## 开始同步

1. 结束设备录音，并关闭网页的实时输入。
2. 在左侧 **录音豆** 页面连接设备。录音豆同一时间只能连一个客户端，先断开手机 App 对它的占用。
3. 点击 **刷新录音列表**，确认要保存的录音已经出现。
4. 点击 **同步全部录音**。只保存其中几条时，勾选后点 **保存所选到资料库**。
5. 在页面下方的 **后台任务** 查看当前第几条／总条数、已完成条数和当前文件百分比。保存成功的录音可以在 **本机资料库** 播放；需要文字或总结时再单独操作。

同步期间保持电脑唤醒、本机服务运行，录音豆保持有电并靠近电脑。启动服务的终端窗口要保持打开。刷新或关闭网页不会取消任务，但电脑休眠、关机或服务停止会影响同步。重新打开网页后可以继续查看后台任务。

## 断线后会怎样

服务会保留已经接收的本机音频缓存。蓝牙意外中断后，会等待原录音豆重新可用，自动重连并从缺失部分接着传；两条录音之间断线也会等待恢复。

单条录音的传输耗时和整批任务都**没有 60 分钟总时长限制**。持续收到新音频的长录音可以继续传；一段时间没有新数据时，服务仍会判断传输是否停滞，必要时重新连接并续传。因此，取消总时长限制不等于忽略卡住的传输。

设备关机、走远或被手机占用时，任务可能保持在等待重连。单纯等待设备重新出现不会因为超过 60 分钟而失败，等待期间也可以在后台任务中取消。

如果某条录音反复尝试仍没有进展，或核验发现完整性冲突，会记录这条失败并继续其余录音。任务会保留已完成和失败清单；只要还有失败项，整批就显示失败，不会显示成全部成功。已成功保存的录音仍留在资料库中。

## 取消后继续

1. 在 **后台任务** 中点击该任务右侧的取消按钮。已经归档的录音和已写入的音频缓存会保留。
2. 要继续时，连接原来的录音豆，关闭实时输入，并等待其他设备任务结束。
3. 找到失败或已取消的同步任务，点击 **继续同步**。没有出现在最近三项里时，展开 **查看最近…项**。

继续同步会重新核验本机已有的归档，跳过完整文件，复用未完成录音的本机缓存。失败清单不会代替重新核验；仍存在完整性问题的录音会再次报告失败。

要把录音豆交回手机，先取消同步，再点击设备页的 **断开连接**。主动断开或改连其他设备会停止旧任务；服务不会替旧任务把设备抢连回来。只有你重新连接原设备并发起同步，才会继续。

**断开连接** 同样会停止批量删除，包括“备份本地后删除”和“直接删除”。已经发出的那条删除仍可能完成；设备回应成功后，任务错误会保留“已删除 N 条”。停止请求发出后不再发送新的删除或目录核验指令，也不会重试删除；重新连接并刷新目录后再确认设备上保留的录音。

## 本机服务重启后继续

服务停止时，正在进行的任务会中断。再次用 `./start.sh` 启动服务后，打开网页，连接原录音豆，在 **后台任务** 找到中断的任务，点击 **继续同步**。中断任务可能显示为失败或已取消，这不表示已完成的文件被丢弃。

服务重启后不会自行重放设备操作。继续下载需要你点击入口；删除设备录音、开始录音和暂停录音没有自动重试。

要复用原来的任务、归档和缓存，请使用同一份本机数据目录。默认目录是项目里的 `.local/data/`；如果配置过其他位置，重新启动时也使用那个位置。同步完成前不要清理其中的音频缓存。

## 为什么旧录音第一次同步比较慢

录音豆通过低功耗蓝牙传输，长录音可能需要较长时间。实时输入期间已缓存在这台电脑的音频可以复用；没有本机缓存的旧录音，第一次仍需完整传输。目前没有 Wi-Fi 传输。

**手机与电脑的缓存不共享。** 即使手机 App 已经接收过同一条录音，也不代表这台电脑已有它的音频。取消后继续或服务重启后继续，复用的是这台电脑保存的数据。

同步完成后，录音豆里的原件仍然存在。删除设备原录音是独立操作，需要另行选择并确认。
