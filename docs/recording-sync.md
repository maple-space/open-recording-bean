# 把录音同步到本机资料库

设备页的 **同步全部录音** 会把当前列表里的录音保存到这台电脑。同步只保存音频，**保留录音豆里的原件，不自动转写或总结**。已在资料库中的录音会先核对本机文件，核验通过后跳过下载。

## 开始同步

1. 结束设备录音，并关闭网页的实时输入。
2. 在左侧 **录音豆** 页面连接设备。录音豆同一时间只能连一个客户端，先断开手机 App 对它的占用。
3. 点击 **刷新录音列表**，确认要保存的录音已经出现。
4. 点击 **同步全部录音**。只保存其中几条时，勾选后点 **保存所选到资料库**。
5. 在页面下方的 **后台任务** 查看当前第几条／总条数、已完成条数和当前文件百分比。保存成功的录音可以在 **本机资料库** 播放；需要文字或总结时再单独操作。

同步期间保持电脑唤醒、本机服务运行，录音豆保持有电并靠近电脑。启动服务的终端窗口要保持打开。刷新或关闭网页不会取消任务，但电脑休眠、关机或服务停止会影响同步。重新打开网页后可以继续查看后台任务。

新建的同步、删除、转写和整理任务只保存录音编号及进度，不在任务历史中重复保存逐字稿或总结。文字仍保存在本机资料库，页面刷新后会显示最新内容；打开或处理单条录音时再读取该条详情。整批任务的完成状态不依赖最后一条录音之后是否被移到废纸篓。旧任务历史保持可读，不自动迁移或清理。

提交同步或 **继续同步** 后，同一标签页即可使用资料库，无需等整批完成或刷新网页。每条录音核验、下载完成或报告该条失败后，就解除本次同步对它的占用；资料库中对应的录音可以随即转写、整理或移到废纸篓。正在处理和还未轮到的录音仍被占用，直到各自处理结束。已有归档也在轮到它并核验后释放。任务结束时页面仍会显示完成或失败提示，并刷新资料库与任务列表。

**先备份再删除** 保持整批占用直到任务结束，因为删除前还要再次核验每条备份。继续同步所用的原始录音清单会完整保留，不会随占用逐条释放而缩短。

## 断线后会怎样

服务会保留已经接收的本机音频缓存。蓝牙意外中断后，会等待原录音豆重新可用，自动重连并从缺失部分接着传；两条录音之间断线也会等待恢复。

Python 3.10 同样支持这些超时重试。即使取消请求恰好与蓝牙写入或设备回应同时完成，任务也会保持取消，不会继续归档；取消时先等待当前异步操作清理完成。相关超时、取消和实时输入路径已在 Python 3.10.20、3.11.10 上通过完整后端离线测试，本轮未新增真机验收。

音频已收齐并核验后，生成本机播放文件不再依赖蓝牙：这时意外掉线，仍会完成归档。用户主动停止、切换设备或连接意图改变时仍会取消。**备份本地后删除** 会在下载返回后继续严格核对连接和会话，掉线或重连后的新会话都不会继续删除。

如果原蓝牙地址失效，服务会扫描候选录音豆，每轮最多连接 3 台，只读取设备信息来核对原设备的序列号。确认序列号不符或信息无法解析的地址，在本次连接期间不再连接，也不占下一轮的 3 个名额；因此排在它们后面的原设备仍有机会被找回。连接失败或超时不能确认身份，之后仍可重试。排除记录只在内存里保存地址，不保存其他设备的序列号；手动连接或断开时清空。只有序列号符合原设备才会读取录音目录和继续同步；首次连接不会自动替换成你没有选择的设备。

单条录音的传输耗时和整批任务都**没有 60 分钟总时长限制**。持续收到新音频的长录音可以继续传；一段时间没有新数据时，服务仍会判断传输是否停滞，必要时重新连接并续传。因此，取消总时长限制不等于忽略卡住的传输。

设备关机、走远或被手机占用时，任务可能保持在等待重连。单纯等待设备重新出现不会因为超过 60 分钟而失败，等待期间也可以在后台任务中取消，或直接点击设备页的 **断开连接 / 停止重连**。停止重连会及时结束等待，无需等到整段重试间隔结束，且不再尝试连接；停止、取消或恢复检查失败时都会释放传输状态；已存音频缓存和任务的 **继续同步** 入口会保留。

如果某条录音反复尝试仍没有进展，或核验发现完整性冲突，会记录这条失败并继续其余录音。任务会保留已完成和失败清单；只要还有失败项，整批就显示失败，不会显示成全部成功。已成功保存的录音仍留在资料库中。

## 取消后继续

1. 在 **后台任务** 中点击该任务右侧的取消按钮。已经归档的录音和已写入的音频缓存会保留。
2. 要继续时，连接原来的录音豆，关闭实时输入，并等待其他设备任务结束。
3. 找到失败或已取消的同步任务，点击 **继续同步**。没有出现在最近三项里时，展开 **查看最近…项**。

继续同步会重新核验本机已有的归档，跳过完整文件，复用未完成录音的本机缓存。原任务中的录音若已不在设备目录，会跳过并在完成提示和任务详情列出编号、数量；若全部消失则提示没有可继续同步的录音。原始清单仍完整保留，只占用本次实际处理的录音。后续续同步任务成功完成同一原始清单后，旧失败或取消任务不再显示继续入口。失败清单不会代替重新核验；仍存在完整性问题的录音会再次报告失败。

要把录音豆交回手机，先取消同步，再点击设备页的 **断开连接**。主动断开或改连其他设备会停止旧任务；服务不会替旧任务把设备抢连回来。只有你重新连接原设备并发起同步，才会继续。

**断开连接** 同样会停止批量删除，包括“备份本地后删除”和“直接删除”。已经发出的那条删除仍可能完成；设备回应成功后，任务错误会保留“已删除 N 条”。停止请求发出后不再发送新的删除或目录核验指令，也不会重试删除；重新连接并刷新目录后再确认设备上保留的录音。

## 本机服务重启后继续

服务停止时，正在进行的任务会中断。再次用 `./start.sh` 启动服务后，打开网页，连接原录音豆，在 **后台任务** 找到中断的任务，点击 **继续同步**。中断任务可能显示为失败或已取消，这不表示已完成的文件被丢弃。

服务重启后不会自行重放设备操作。继续下载需要你点击入口；删除设备录音、开始录音和暂停录音没有自动重试。

要复用原来的任务、归档和缓存，请使用同一份本机数据目录。默认目录是项目里的 `.local/data/`；如果配置过其他位置，重新启动时也使用那个位置。同步完成前不要清理其中的音频缓存。

## 为什么旧录音第一次同步比较慢

录音豆通过低功耗蓝牙传输，长录音可能需要较长时间。实时输入期间已缓存在这台电脑的音频可以复用；没有本机缓存的旧录音，第一次仍需完整传输。目前没有 Wi-Fi 传输。

**手机与电脑的缓存不共享。** 即使手机 App 已经接收过同一条录音，也不代表这台电脑已有它的音频。取消后继续或服务重启后继续，复用的是这台电脑保存的数据。

同步完成后，录音豆里的原件仍然存在。删除设备原录音是独立操作，需要另行选择并确认。

## 任务临时文件

本次导出失败或取消时，只把它新建的未完成文件、未归档的导出文件移入 macOS 废纸篓；任务结束后只回收自己的空工作目录。已验证的帧缓存保留，继续同步时可以重新生成播放文件。既有残留文件以及非空工作目录不会自动清理；若系统拒绝移入废纸篓，文件会原地保留并记录警告，不影响已经成功归档的录音。
