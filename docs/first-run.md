# 新电脑首次运行指南

本项目在 Mac 上运行。网站、后端和专属声卡源码在同一仓库；网站启动脚本自动准备应用依赖和本机识别模型，系统声卡首次安装需要单独完成。

支持 Intel 与 Apple Silicon，无需电脑内置麦克风：声音来自录音豆，专属声卡把网页送来的声音提供给输入法。完整设置和故障排查见 [macOS 安装与使用指南](macos-setup.md)。

## 1. 提前准备

- macOS 11 或更新。已在 macOS 15 上完成功能验证，11 到 14 还没有实机验证。
- Node.js 22.12 或更新，也支持 20.x 中的 20.19 及以上版本。
- Python 3.10–3.13；如果已安装 uv，启动脚本可用 uv 准备 Python 3.12。
- 首次保持联网：需要下载应用依赖和约 270 MB 的模型。270 MB 仅指模型文件，不包含 Python、Node.js 和应用依赖。

在新电脑用 Git 克隆源码并启动：

```bash
git clone https://github.com/maple-space/open-recording-bean.git
cd open-recording-bean
./start.sh
```

若运行时提示 `Permission denied`，可改用 `bash start.sh`。脚本会创建项目自己的 `.venv`、安装依赖、构建网页、下载并校验模型，然后启动本机服务并打开 `http://127.0.0.1:8875`。不需要手动逐项执行 pip/npm 安装。

脚本不会替你安装缺少的 Node.js 或 uv；没有合适 Python 且没有 uv 时，也会提示先安装 Python。按终端提示补好基础环境，再次运行即可。

## 2. 模型下载与配置

正常使用不需要填模型路径或 API Key。启动脚本与后端默认使用相同目录，模型完整后自动识别，优先使用 SenseVoice Small。

| 文件 | 用途 | 默认位置（相对项目目录） |
| --- | --- | --- |
| `model.int8.onnx`，约 239 MB | SenseVoice Small 语音识别模型 | `.local/asr/sensevoice/` |
| `tokens.txt`，约 0.32 MB | 与语音模型配套的词表，必须一起保留 | `.local/asr/sensevoice/` |
| `3dspeaker_speech_campplus_sv_zh-cn_16k-common.onnx`，约 28 MB | CAM++ 说话人模型 | `.local/asr/speaker/` |

模型的精确版本、下载地址、文件大小及 SHA-256 在 [scripts/fetch_models.py](../scripts/fetch_models.py) 中固定。脚本先尝试 Hugging Face，失败后尝试镜像；CAM++ 还配置了 GitHub 备用地址。每个文件通过大小和 SHA-256 校验后才会放到正式路径，已有完整文件不会重复下载。

中断时保留 `.part` 文件；再次运行会在下载源支持续传时接着下载。源不支持续传时会重下该文件，无需自行拼接。源码仓库忽略 `.local/`，因此别人下载源码时不带你的模型、录音、文字记录或个人设置。

**单独补齐模型或重试下载：** 在项目目录打开另一个终端运行，不必停止正在运行的网站：

```bash
./start.sh models
```

**指定镜像：**

```bash
HF_ENDPOINT=https://hf-mirror.com ./start.sh models
```

**检查依赖与模型是否就绪：**

```bash
./start.sh doctor
```

**只校验模型文件的大小和 SHA-256，不下载：** 项目环境创建后运行：

```bash
.venv/bin/python scripts/fetch_models.py --check
```

完整时显示“模型已经齐全”并返回成功；缺少或校验不通过时会列出对应文件，再运行 `./start.sh models` 补齐。

下载完成后，首页点“重新检测”，应看到“准备本机识别模型 · 已完成”。实时输入中开启“在本页显示文字”，即可使用本机识别；CAM++ 就绪后，下次开启实时输入可勾选“区分说话人”。说话人编号只区分声音，不识别姓名。

- SenseVoice 或其词表缺失：本地实时文字不可用；专属声卡传声仍可使用。
- 仅 CAM++ 缺失：语音识别仍可用，但没有说话人区分。
- 模型下载失败不会伪装成已就绪，终端会给出重试方法；无需重启电脑。
- 模型下载好后，本机识别不需联网或 API Key。Typeless、豆包及可选的云端纪要整理使用各自的服务与设置，不属于这两个本机模型。

### 离线拷贝或自定义目录

若目标电脑无法下载模型，可从已经准备好的电脑复制完整 `.local/asr/` 到新项目的同名目录，再执行上述 `--check` 校验。新电脑仍需先准备 Python/Node.js 和应用依赖；只复制模型不等于整套程序已安装。

默认目录最省事。需要自定义时，下载和每次启动必须使用同一个 `RECORDING_ASR_DIR`：

```bash
RECORDING_ASR_DIR="$PWD/model-files" ./start.sh models
RECORDING_ASR_DIR="$PWD/model-files" ./start.sh
```

目录内仍保持 `sensevoice/` 和 `speaker/` 两个子目录。首次正常安装不要设置 `RECORDING_SKIP_MODELS=1`，它会跳过自动下载检查。

## 3. 首次连接与声卡设置

1. 只看网页文字可以不安装声卡；要把声音送入输入法，从 [同仓库的声卡 Release](https://github.com/maple-space/open-recording-bean/releases/tag/audio-v1.0.1) 下载 `RecordingBeanAudio2ch-1.0.1-release.zip`，解压后双击“安装并启用.command”，在本机完成管理员认证。Intel / Apple Silicon 用同一个包，普通使用者无需 Xcode。详见 [专属声卡安装说明](../tools/recording-bean-audio/README.md)。`.pkg` 只安装声卡，不安装网站或模型。
2. 在网页搜索并连接录音豆，系统提示蓝牙权限时允许。录音豆同一时间只能连接一个客户端，先断开手机 App 对它的占用。
3. 连接后点击设备页的 **进入实时输入**。网页输出与输入法麦克风都选 **Recording Bean Audio 2ch**，再开启实时输入。声卡与这两个识别模型各自独立，安装模型不会自动修改输入法的麦克风。

设备页的“仅在录音豆上录音”是折叠的独立控制区：“开始设备录音”只让录音豆录制并保存到设备，不开启网页文字或向输入法传声。日常当电脑麦克风用，请走“进入实时输入”。

录音目录在连接或重连时读取一次；新录音完成后，可以点击“刷新录音列表”。网页不会自己去读设备目录。页面定时更新的是本机服务已有的状态，这种查询不发送蓝牙指令，也不锁住操作按钮。手动刷新、下载和删除等设备任务仍需串行执行；开启实时输入时先关闭它，再管理录音文件。

### 把设备录音保存到电脑

结束设备录音并关闭实时输入后，在 **录音豆** 页面刷新列表，点击 **同步全部录音**。同步保留设备原件，不自动转写或总结；本机已有的归档核验通过后会跳过。页面下方的 **后台任务** 显示逐条进度和完成／失败清单。

蓝牙意外断开后会自动等待原设备恢复，复用本机缓存补传缺口。单文件和整批任务都没有 60 分钟总时长限制；设备离线等待期间可以取消。取消后，或本机服务重启后，连接原设备，在失败或已取消的任务旁点击 **继续同步**。

同步期间保持电脑唤醒、服务运行。关闭网页不影响后台任务；手机 App 的缓存不能代替这台电脑的缓存。完整步骤及失败处理见 [录音同步指南](recording-sync.md)。

## 4. 以后怎么启动

进入项目目录，运行 `./start.sh` 即可。已准备好的依赖和通过校验的模型会复用；声卡由 macOS 加载，不需要另开声卡程序。启动服务的终端窗口保持打开，网页可按需要关闭和重开。

新电脑通常仍需完成管理员认证、蓝牙权限和首次设备选择，这些不是脚本静默代办的步骤。

## 5. 更新源码

结束当前实时输入；若正在同步录音，先在后台任务中取消。在启动网站的终端按 Ctrl+C 正常停止服务，然后在项目目录运行：

```bash
git pull --ff-only
./start.sh
```

启动脚本会按需要更新依赖、重建网页，完整模型继续复用。先前取消的同步任务可在重新连接录音豆后点击“继续同步”，复用已归档的录音和本机缓存。若 Git 提示本地源码有改动，先保留自己的修改再处理合并，不要用强制重置覆盖。声卡版本没有变化时不需重装；有变化时按该版本的 Release 说明升级。
